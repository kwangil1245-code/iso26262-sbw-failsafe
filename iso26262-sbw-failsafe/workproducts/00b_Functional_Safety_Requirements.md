---

> 본 문서는 HARA에서 도출된 Safety Goal을 기반으로 시스템이 수행해야 하는 Functional Safety Requirement(FSR)를 정의한다. 구체적인 고장 감지 기준, 안전 상태, 출력 제어 방법 및 정상 복귀 조건은 후속 시스템 및 SW 요구사항에서 구체화한다.

## 1. 목적 및 범위

본 문서는 `00a_HARA_Worksheet.md`에서 식별한 Hazardous Event와 Safety Goal을 기능 안전 요구사항으로 구체화하는 것을 목적으로 한다.

HARA에서 식별한 Hazardous Event와 Safety Goal은 다음과 같다.

* **HE-01**: 비정상 조향 정보 또는 조향 제어 기능의 이상으로 운전자 의도와 다른 조향 출력이 발생함
* **SG-01**: 운전자 의도와 다른 비의도 조향 출력이 발생하지 않아야 한다

HE-01의 주요 원인은 다음과 같이 구분한다.

* 조향 정보의 통신 이상
* 유효하지 않은 조향 입력
* 조향 제어 관련 SW 실행 이상

SG-01을 만족하기 위해 각각의 원인이 비의도 조향 출력으로 이어지지 않도록 기능 안전 요구사항을 정의한다.

Alive Counter 판정 조건, 조향각 유효 범위, SW 실행 감시 방법, Fault 판정 횟수, 안전 상태에서의 출력값 및 정상 복귀 조건과 같은 구체적인 구현 방법은 후속 시스템 및 SW 요구사항에서 정의한다.

---

## 2. 요구사항 관리 원칙

* FSR은 Safety Goal을 만족하기 위해 시스템이 수행해야 하는 안전 기능을 정의한다.
* FSR은 고장이 비의도 조향 출력으로 이어지는 것을 방지하는 관점에서 정의한다.
* 구체적인 고장 감지 기준과 구현 방법은 FSR 단계에서 정의하지 않는다.
* 모든 FSR은 상위 Safety Goal인 SG-01과 추적 관계를 유지한다.
* 각 FSR은 후속 시스템 및 SW 요구사항으로 구체화한다.
* 통신 이상, 입력 이상 및 SW 실행 이상에 대한 구체적인 대응 방법은 하위 요구사항과 설계 단계에서 정의한다.

## 4. Safety Goal별 FSR 전개

### SG-01: 비의도 조향 출력 방지

#### Hazardous Event

비정상 조향 정보 또는 조향 제어 기능의 이상으로 운전자 의도와 다른 조향 출력이 발생하고, 차량이 의도하지 않은 방향으로 움직여 충돌할 수 있음.

#### Safety Goal

**SG-01: 운전자 의도와 다른 비의도 조향 출력이 발생하지 않아야 한다.**

#### 관련 Functional Safety Requirements

| FSR ID  | 주요 고장 원인          | 안전 요구사항                    |
| ------- | ----------------- | -------------------------- |
| FSR_001 | 조향 정보의 통신 이상      | 통신 이상으로 인한 비의도 조향 출력 방지    |
| FSR_002 | 유효하지 않은 조향 입력     | 입력 이상으로 인한 비의도 조향 출력 방지    |
| FSR_003 | 조향 제어 관련 SW 실행 이상 | SW 실행 이상으로 인한 비의도 조향 출력 방지 |

## 5. 고장 원인과 FSR 관계

비의도 조향 출력으로 이어질 수 있는 주요 원인과 관련 FSR은 다음과 같다.

| 고장 원인    | 고장 예시                             |  관련 FSR |
| -------- | --------------------------------- | :-----: |
| 통신 이상    | 조향 정보 수신 실패, 데이터 갱신 중단, 데이터 순서 이상 | FSR_001 |
| 입력 이상    | 허용 범위를 벗어난 조향 입력, 유효하지 않은 데이터     | FSR_002 |
| SW 실행 이상 | 조향 제어 기능 미실행, 주기적 기능의 비정상 실행      | FSR_003 |

위 고장 원인은 후속 시스템 및 SW 요구사항에서 검출 조건과 대응 방법으로 구체화한다.

## 7. 후속 개발 단계 전개

### FSR_001: 통신 이상으로 인한 비의도 조향 출력 방지

후속 시스템 및 SW 요구사항에서 다음 내용을 구체화한다.

* 조향 정보의 수신 상태를 판단하는 방법
* 조향 정보가 정상적으로 갱신되는지 판단하는 방법
* 통신 이상을 확정하는 조건
* 통신 이상 데이터의 제어 사용 방지
* 통신 이상 감지 시 안전 상태 전환
* 안전 상태에서의 조향 출력 제한
* 통신 정상화 이후 정상 상태 복귀 조건

### FSR_002: 유효하지 않은 입력으로 인한 비의도 조향 출력 방지

후속 시스템 및 SW 요구사항에서 다음 내용을 구체화한다.

* 조향 입력의 유효성을 판단하는 기준
* 조향 입력의 허용 범위
* 입력 이상을 확정하는 조건
* 유효하지 않은 입력의 제어 사용 방지
* 입력 이상 감지 시 안전 상태 전환
* 안전 상태에서의 조향 출력 제한
* 정상 입력 확인 이후 정상 상태 복귀 조건

### FSR_003: SW 실행 이상으로 인한 비의도 조향 출력 방지

후속 시스템 및 SW 요구사항에서 다음 내용을 구체화한다.

* 조향 제어 관련 SW 기능의 실행 상태 감시 방법
* SW 미실행 또는 비정상 실행 판단 조건
* SW 실행 이상 감지 방법
* SW 실행 이상 감지 시 안전 상태 전환
* 안전 상태에서의 조향 출력 제한
* SW 실행 정상화 이후 정상 상태 복귀 조건

## 8. 프로젝트 적용 범위

본 프로젝트에서는 다음 기능을 중심으로 구현 및 검증한다.

* Alive Counter를 이용한 조향 정보 갱신 상태 확인
* 조향각 유효 범위 확인
* 이상 정보의 제어 사용 방지
* 이상 감지 시 NORMAL 상태에서 FAIL-SAFE 상태로 전환
* FAIL-SAFE 상태에서 위험한 조향 출력 차단
* 정상 조건이 연속적으로 확인된 이후 NORMAL 상태로 복귀

SW 실행 상태 감시는 기능 안전 요구사항과 시스템 요구사항으로 정의한다. 실제 구현 및 검증 범위는 프로젝트에서 적용한 실행 감시 방법에 따라 별도로 명시한다.
