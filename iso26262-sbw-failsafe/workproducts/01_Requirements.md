**Document ID**: STEER-01-SRS  
**ISO 26262 Reference**: Part 4, System Requirements Specification  
**ASPICE Reference**: SYS.2 (System Requirements Analysis)  
**Version**: 1.6  
**Date**: 2026-08-27  
**Status**: Draft  
**Project Title**: AUTOSAR 기반 조향 관련 오류에 대한 복구 및 진단 시스템  
**Subtitle**: 조향 데이터 갱신 이상, 비정상 입력 및 SW 실행 이상에 대한 시스템 요구사항

---

> 본 문서는 HARA에서 도출된 Safety Goal을 기반으로 시스템이 수행해야 하는 기능과 안전 동작을 정의한다. 구체적인 진단 메커니즘, Fault 판정 횟수, 조향각 유효 범위, AUTOSAR 모듈 구성 및 PWM 계산 방식은 후속 시스템 설계 및 SW 요구사항·설계 단계에서 구체화한다.

## 1. 목적 및 범위

본 문서는 HARA에서 식별한 주요 Hazardous Event와 Safety Goal을 시스템 수준 요구사항으로 구체화하는 것을 목적으로 한다.

HARA에서는 다음 세 가지 주요 위험을 대상으로 한다.

- **HC-01 / SG-01**: 조향 데이터 갱신 이상으로 인한 위험한 조향 출력 방지
- **HC-02 / SG-02**: 비정상적인 조향 입력으로 인한 위험한 조향 출력 방지
- **HC-03 / SG-03**: 조향 제어 관련 SW 실행 이상으로 인한 위험한 조향 출력 방지

본 시스템은 조향 입력의 수집 및 전달, 데이터 갱신 상태 감시, 입력 유효성 검사, 내부 실행 상태 감시, 안전 상태 전환 및 출력 제한, 정상 상태 복귀와 조향 출력을 수행해야 한다.

## 4. HARA 기반 안전 요구사항

### 4.1 HC-01 / SG-01

**Hazardous Event**  
조향 데이터의 갱신 이상으로 오래된 조향 입력이 사용되어 운전자 의도와 다른 조향이 발생함.

**Safety Goal**  
**SG-01:** 조향 데이터의 갱신 이상을 감지하고 위험한 조향 출력이 발생하지 않도록 해야 한다.

**관련 시스템 요구사항**

| Req. ID | 역할 |
|---|---|
| Req_002 | 조향 데이터의 지속적인 전달 |
| Req_003 | 조향 데이터 갱신 상태 감시 |
| Req_006 | 이상 감지 시 안전 상태 전환 |
| Req_007 | 안전 상태에서 위험한 출력 방지 |

---

### 4.2 HC-02 / SG-02

**Hazardous Event**  
비정상적인 조향 입력이 정상 입력으로 사용되어 운전자 의도와 다른 조향이 발생함.

**Safety Goal**  
**SG-02:** 비정상적인 조향 입력을 감지하고 해당 입력으로 인해 위험한 조향 출력이 발생하지 않도록 해야 한다.

**관련 시스템 요구사항**

| Req. ID | 역할 |
|---|---|
| Req_001 | 운전자 조향 입력 수집 |
| Req_004 | 조향 입력 유효성 판단 |
| Req_006 | 이상 감지 시 안전 상태 전환 |
| Req_007 | 안전 상태에서 위험한 출력 방지 |

---

### 4.3 HC-03 / SG-03

**Hazardous Event**  
조향 제어 관련 SW 실행 이상으로 오래된 데이터 또는 비정상적인 제어 결과가 사용되어 운전자 의도와 다른 조향이 발생함.

**Safety Goal**  
**SG-03:** 조향 제어 관련 SW 실행 이상을 감지하고 위험한 조향 출력이 발생하지 않도록 해야 한다.

**관련 시스템 요구사항**

| Req. ID | 역할 |
|---|---|
| Req_005 | 조향 제어 관련 내부 실행 상태 감시 |
| Req_006 | 이상 감지 시 안전 상태 전환 |
| Req_007 | 안전 상태에서 위험한 출력 방지 |

## 5. HARA-시스템 요구사항 추적성

| HARA ID | Safety Goal | 관련 시스템 요구사항 |
|---|---|---|
| **HC-01** | SG-01 | Req_002, Req_003, Req_006, Req_007 |
| **HC-02** | SG-02 | Req_001, Req_004, Req_006, Req_007 |
| **HC-03** | SG-03 | Req_005, Req_006, Req_007 |

Req_006과 Req_007은 특정 Hazard 하나에 종속되는 요구사항이 아니라, HC-01~HC-03에서 이상이 감지된 이후 공통적으로 적용되는 안전 상태 관리 및 출력 제한 요구사항으로 정의한다.

Req_008은 HARA의 개별 Safety Goal에 직접 대응하는 요구사항이 아니라, 안전 상태 진입 후 시스템의 정상 기능을 안전하게 회복하기 위한 시스템 기능 요구사항으로 관리한다.

---

## 6. 정상 상태 복귀 요구사항

안전 상태 진입 후 Fault 원인이 제거된 경우 시스템은 정상 기능으로 복귀할 수 있어야 한다.

정상 상태 복귀는 새로운 Hazardous Event 또는 Safety Goal로 정의하지 않고, 안전 상태 이후 시스템 기능을 회복하기 위한 요구사항으로 정의한다.

**Req_008**에 따라 시스템은 정의된 정상 조건이 지속적으로 충족되는 경우에만 정상 상태로 복귀해야 한다.

정상 여부를 판단하기 위한 구체적인 조건과 연속 정상 판정 횟수는 후속 SW 요구사항에서 정의한다.

## 9. SW 요구사항으로의 전개 원칙

`03_SW_Requirements.md`에서는 본 시스템 요구사항을 SW가 직접 판단하고 실행할 수 있는 수준으로 상세화한다.

다음과 같은 구체적인 동작 조건은 SW 요구사항 단계에서 정의한다.

- 조향 데이터 송신 주기
- 데이터 갱신 여부 판단 방식
- Alive Counter를 이용한 Fault 판정 조건
- 조향 입력 유효 범위
- SW 실행 상태 감시 조건
- FAIL-SAFE 상태에서의 출력 제한 조건
- 정상 상태 복귀를 위한 연속 정상 판정 조건

다음과 같은 SW 구조 및 구현 정보는 후속 SW Architecture 및 Detailed Design 단계에서 정의한다.

- AUTOSAR SWC 구성
- Port 및 Interface
- Runnable 및 Event
- RTE API
- 내부 상태 변수 및 Counter
- WdgM Supervised Entity 및 Checkpoint
- PWM 계산 로직
- Task Mapping
