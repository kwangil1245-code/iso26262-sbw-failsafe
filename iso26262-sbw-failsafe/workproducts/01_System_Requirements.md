> 본 문서는 `00b_Functional_Safety_Requirements.md`에서 정의한 Functional Safety Requirement(FSR)와 시스템의 일반 기능 요구를 시스템 수준 요구사항으로 구체화한다. HARA에서 도출된 Safety Goal은 FSR을 통해 안전 기능으로 전개되며, 본 문서에서는 해당 FSR을 안전 관련 시스템 요구사항으로 구체화한다. 구체적인 진단 메커니즘, Fault 판정 조건, 조향각 유효 범위 및 AUTOSAR 구현 구조는 후속 시스템 설계와 SW 요구사항·설계 단계에서 단계적으로 정의한다.

## 1. 목적 및 범위

본 문서는 `00b_Functional_Safety_Requirements.md`에서 정의한 Functional Safety Requirement(FSR)와 시스템의 일반 기능 요구를 시스템 수준 요구사항으로 구체화하는 것을 목적으로 한다.

HARA에서는 다음 세 가지 주요 위험을 대상으로 한다.

- **HC-01 / SG-01**: 조향 정보 전달 과정의 통신 이상으로 인한 위험한 조향 출력 방지
- **HC-02 / SG-02**: 비정상적인 조향 입력으로 인한 위험한 조향 출력 방지
- **HC-03 / SG-03**: 조향 제어 관련 SW 실행 이상으로 인한 위험한 조향 출력 방지

본 시스템은 다음 기능을 수행해야 한다.

- 운전자 조향 입력 수집 및 전달
- 조향 정보 수신 상태 감시
- 조향 입력 유효성 검사
- 조향 제어 관련 기능의 실행 상태 감시
- 이상 감지 시 안전 상태 전환
- 안전 상태에서 위험한 조향 출력 제한
- 정상 조건 충족 시 정상 상태 복귀
- 정상 상태에서 조향 제어값 계산 및 출력

안전 관련 요구사항은 다음과 같은 추적 구조를 따른다.

`Hazardous Event → Safety Goal → FSR → System Requirement → System Design → SW Requirement → SW Design → Verification`

## 2. 요구사항 관리 원칙

본 문서에서는 일반 시스템 요구사항과 안전 관련 시스템 요구사항을 하나의 시스템 요구사항 ID 체계로 통합 관리한다.

- **Req_001, Req_002, Req_009, Req_010**은 정상적인 조향 기능을 정의한 일반 시스템 요구사항이다.
- **Req_003~Req_007**은 `00b_Functional_Safety_Requirements.md`에서 정의한 FSR을 시스템 수준에서 구체화한 안전 관련 시스템 요구사항이다.
- **Req_008**은 안전 상태 진입 후 정상 기능을 안전하게 회복하기 위해 시스템 수준에서 파생된 상태 관리 요구사항이다.
- 안전 관련 시스템 요구사항은 상위 FSR과 추적 관계를 유지한다.
- 후속 SW 요구사항은 관련 시스템 요구사항을 역참조하여 상·하위 요구사항 간 양방향 추적성을 유지한다.

## 5. 안전 관련 시스템 요구사항 및 FSR 추적성

### 5.1 HC-01 / SG-01

**Hazardous Event**  
조향 정보 전달 과정의 통신 이상으로 운전자 의도와 다른 조향 출력이 발생함.

**Safety Goal**  
**SG-01:** 조향 정보가 정상적으로 수신되지 않는 상태를 감지하고 운전자 의도와 다른 위험한 조향 출력이 발생하지 않도록 해야 한다.

**관련 FSR**

| FSR ID | 역할 |
|---|---|
| FSR_001 | 조향 정보 수신 상태 감시 및 이상 감지 |
| FSR_004 | 이상 감지 시 안전 상태 전환 |
| FSR_005 | 안전 상태에서 위험한 조향 출력 방지 |

**FSR-시스템 요구사항 추적성**

| FSR ID | Req. ID | 시스템 수준 구체화 |
|---|---|---|
| FSR_001 | Req_003 | 조향 정보의 정상 수신 여부 감시 및 이상 감지 |
| FSR_004 | Req_006 | 조향 정보 수신 이상 감지 시 안전 상태 전환 |
| FSR_005 | Req_007 | 안전 상태에서 위험한 조향 출력 제한 |

**Hazardous Event**  
비정상적인 조향 입력이 정상 입력으로 사용되어 운전자 의도와 다른 조향이 발생함.

**Safety Goal**  
**SG-02:** 비정상적인 조향 입력을 감지하고 해당 입력으로 인해 위험한 조향 출력이 발생하지 않도록 해야 한다.

## 6. 정상 상태 복귀 요구사항

안전 상태 진입 후 Fault 원인이 제거된 경우 시스템은 정상 기능으로 복귀할 수 있어야 한다.

정상 상태 복귀는 별도의 Safety Goal 또는 FSR에서 직접 도출하지 않고, 안전 상태 이후 시스템 기능을 안전하게 회복하기 위해 시스템 수준에서 파생된 상태 관리 요구사항으로 정의한다.

**Req_008**에 따라 시스템은 안전 상태 진입 원인이 해소되고 정의된 정상 조건이 지속적으로 충족되는 경우에만 정상 상태로 복귀해야 한다.

정상 여부를 판단하기 위한 구체적인 조건과 연속 정상 판정 횟수는 후속 SW 요구사항에서 정의한다.

## 7. 일반 시스템 요구사항

다음 요구사항은 조향 시스템의 정상 기능 수행을 위해 정의한다.

| Req. ID | 일반 시스템 기능 |
|---|---|
| Req_001 | 운전자 조향 입력 수집 |
| Req_002 | 수집된 조향 정보 전달 |
| Req_009 | 유효한 조향 입력을 기반으로 조향 제어값 계산 |

일반 시스템 요구사항은 Safety Goal 또는 FSR에서 직접 도출된 안전 관련 시스템 요구사항은 아니지만, 안전 관련 기능의 정상적인 동작에 영향을 줄 수 있으므로 후속 설계 및 검증 과정에서 함께 관리한다.

| Req_003 | FSR_001 | 조향 정보의 정상 수신 여부를 판단하기 위한 시스템 수준 감시 기능 |
| Req_004 | FSR_002 | 조향 입력 유효성을 판단하기 위한 시스템 수준 진단 기능 |
| Req_005 | FSR_003 | 조향 제어 관련 기능의 실행 상태를 감시하기 위한 시스템 수준 감시 기능 |
| Req_006 | FSR_004 | 이상 감지 결과에 따른 안전 상태 판단 및 전환 구조 |
| Req_007 | FSR_005 | 안전 상태에서 위험한 조향 출력을 제한하기 위한 출력 제어 구조 |
| Req_008 | Derived | Fault 해소 후 정상 상태로 안전하게 복귀하기 위한 상태 관리 구조 |
| Req_009, Req_010 | 일반 기능 요구 | 정상 상태에서의 조향 제어값 계산 및 출력 장치 제어 구조 |
